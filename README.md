# 가격 검색

업체 단가표와 실제 발주 이력을 한 표에 모아 찾아보는 페이지입니다.
값을 고치면 **누가 언제 무엇을 바꿨는지** 이력이 남습니다.

```
단가검색-site/
├─ index.html          앱 본체 (데이터 내장 · 빌드 불필요 · 더블클릭 실행 가능)
├─ catalog.json        단가표 정규화 데이터
├─ purchases.json      발주 이력 집계
├─ api/store.js        수정분·이력 서버 저장소 (Vercel Blob)
├─ package.json        @vercel/blob
├─ vercel.json
├─ rebuild.sh          원본이 바뀌었을 때 다시 만드는 스크립트
└─ tools/
   ├─ xlsx2tsv.pl      xlsx → TSV (OOXML 직접 파싱, 파이썬 불필요)
   ├─ pdf2txt.pl       PDF → 텍스트 (CID 폰트 ToUnicode 디코딩)
   ├─ build.pl         → catalog.json
   └─ buyagg.pl        구매통계 → purchases.json
```

## 배포 (Vercel)

### 1. 올리기

GitHub은 선택입니다.

```bash
cd "D:/Google Drive/37.구매시스템/2026_단가계약/단가검색-site"
npx vercel
```

GitHub을 쓰실 경우 새 프로젝트를 만들지 말고 **기존 프로젝트 Settings → Git → Connect** 로 붙이세요.
Framework Preset **Other**, Build Command·Output Directory **비워둠**.
`api/` 는 Vercel이 자동으로 함수로 잡고 `@vercel/blob` 도 알아서 설치합니다.

### 2. 저장소 연결 — 이걸 해야 수정이 서버에 남습니다

Storage → **Create Database** → **Blob** → Create → Deployments 에서 **Redeploy**.

안 하면 수정이 **각자 브라우저에만** 저장됩니다. 화면 상단 배지로 상태가 보입니다:
`서버 저장 · 팀 공유`(녹색) / `이 브라우저에만 저장됨`(빨강).

확인: 배포 주소 뒤 `/api/store` 를 열어 `{"overrides":{},...}` 가 나오면 정상.

### 3. 접근 제한

Settings → Deployment Protection → **Vercel Authentication**.
단가는 대외비인데 기본값은 링크만 알면 누구나 열립니다.

## 원본이 바뀌면

```bash
bash rebuild.sh                                         # 단가표 갱신
perl tools/buyagg.pl <구매통계 TSV> > purchases.json      # 발주 이력 갱신
```

`tools/build.pl` 의 업체 블록이 컬럼 위치를 지정합니다. 새 업체가 늘면 그 블록만 추가하면 됩니다.

**다시 만들어도 사용자가 고친 값과 이력은 지워지지 않습니다.** 원본 위에 수정분을 덧씌우는 구조입니다.
